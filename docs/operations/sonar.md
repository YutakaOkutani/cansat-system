# 超音波センサの接続・診断と最終接近

READMEから移した実機向けの手順と設計説明。実行コマンドはリポジトリのルートで実行する。現在の設定値は本文末尾の実装を参照する。

## 超音波センサの使い方

HC-SR04系のTRIG/ECHO方式を、`gpiozero.DistanceSensor`を拡張した`SonarSensor`と`LGPIOFactory`で読み取る。平滑化済みのキャッシュではなく、各測距試行の距離・成否・取得時刻・連番を記録する。接続方式が直結でもレベル変換経由でも、ソフトウェアの設定は共通。

| センサ端子 | 接続先（GPIO番号はBCM） |
| --- | --- |
| VCC | 使用するモジュールの仕様に合った電源（標準HC-SR04は5 V） |
| GND | Raspberry Piと共通のGND |
| TRIG | GPIO23（40ピンヘッダの物理16番） |
| ECHO | GPIO24（物理18番）。以下の条件で直結またはレベル変換を選ぶ |

**ECHOの接続は使用する個体・モジュールの出力仕様によって選ぶ。** 使用する電源条件でECHOが3.3 V GPIOの入力仕様に適合する製品や、変換回路を備えたモジュールは直結できる。標準HC-SR04などECHOが5 V出力の場合は、外付け分圧回路またはレベル変換回路を介して接続する。現行基板自体にはECHOのレベル変換回路がない。出力仕様が不明な場合は、接続前に仕様書やECHOのパルス電圧を確認して接続方式を選ぶ。直結で測定できた実績だけでは、GPIOの入力電圧範囲に収まっているかまでは判断できない。

5 V ECHOを使う場合の分圧例（3.3 V出力の個体にはこの分圧を重ねない）：

```text
センサ ECHO -- 10 kΩ --+-- GPIO24
                       |
                      10 kΩ
                       |
                      GND
```

この例は5 Vを約2.5 Vに下げる。使用するRaspberry PiのHigh入力条件も確認する。接続条件の参照先：[Raspberry Pi GPIO仕様](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)、[GPIO ZeroのDistanceSensor説明](https://gpiozero.readthedocs.io/en/v1.6.0/api_input.html#distancesensor-hc-sr04)。

配線後、リポジトリのルートから単体診断を実行する。`main.py`などGPIOを使う他のプログラムは終了しておく。

```bash
source venv/bin/activate
python3 runs/diag/sonar.py --interval 0.2 --duration 30
```

センサの正面に平らな物体を置き、距離を変えて表示を確認する。`--duration`を省略するとCtrl+Cまで継続する。診断はモーターを動かさず、終了時にGPIOを解放する。

* `VALID distance=... cm sequence=...`：新しい測距で得た有効な距離と試行番号。
* `INVALID`：無反射、範囲外、または取得時刻が古い。直前の距離は参考表示で、制御には使わない。
* 終了時の`Summary`は診断で観測した有効・無効の回数。有効値が一度もなければ終了コード1。

本番では約0.2秒ごとに最新の測距試行を状態へ反映する。採用範囲は2 cm以上4 m未満、取得から0.5秒未満。無反射の新しい試行は直ちに無効とし、同じ試行を読み直しても取得時刻は更新しない。この範囲はソフトウェアの採用条件であり、実機の精度保証ではない。

## 超音波を使ったゴールへの最終接近

**超音波だけによる障害物検知・自動回避は撤去した。** 草への反射によってPhase 2・3・4の走行を停止・旋回させない。測距だけで走行可能性やスタックを判断しない。将来はカメラによる物体・走行可能領域の認識、距離、実際の移動量などを組み合わせた障害物検知を検討する。現時点ではその回避機能は実装していない。

ゴール条件は機体と赤コーンの接触を目指す。車体先端はソナー面より約2 cm前にあるというテストコードによる実測に基づき、基準を緩い側にやや倒した**ソナー面から3 cm以内を停止目標**にする。10 cmで自動的に成功扱いする等の緩和条件は設けない。車体寸法は未測定であり、コーンの斜面への反射もあるため、近接確認と物理的な接触確認は区別する。

| 段階 | 動作 |
| --- | --- |
| Phase 4 | カメラでコーン候補を探索・確認 |
| Phase 5 | カメラで接近・整列。60 cm以内の新しい測距と、正面のコーン候補が2組続けて整合したら停止してPhase 6へ。占有面積だけでは移行・成功にしない |
| Phase 6 | 出力45%・最長0.15秒の前進指令と、停止後0.3秒の待機・再観測を繰り返す。3 cm以内なら前進を止め、停止後に取得した画像と距離を3組確認する |
| Phase 7 | 停止して終了。近接確認、観測喪失、時間切れを別の終了理由として記録 |

画像上のコーンがソナーの正面にあり、画像と測距の時刻差が0.3秒以内の場合に距離を採用する。画像の大きさは極端に遠い候補を除く補助条件として残す。カメラとソナーは正面が一致する取付を前提とする。同じ画像や測距の使い回し、単発の近距離反射だけでは確認回数を増やさない。

最終接近中は欠測、古い距離、視覚対象の消失・ずれで停止し、停止したまま再観測する。観測を回復できなければ終了する。Phase 6は20秒を上限とし、距離が縮まらなくても無期限に押し続けない。時間切れから固定時間前進へ切り替える動作はない。モーター側でも前進指令の期限とセンサの鮮度を確認する（実際のパルス長・停止位置には処理時間と慣性が影響する）。

終了理由`GOAL_PROXIMITY_CONFIRMED`は「カメラとソナーで3 cm以内を停止後に確認」を表し、接触センサによる接触確認ではない。`GOAL_OBSERVATION_LOST`、`GOAL_RANGE_UNCONFIRMED`、`GOAL_APPROACH_TIMEOUT`は未確認での終了。従来の`GOAL_REACHED`は過去ログとの互換のために残すが、新しい経路では発行しない。

実機投入前に車体先端の張り出しを測り、実際のコーンと草のある地面で、取付角度・高さ、2〜10 cm付近の測距、接触位置、停止後の慣性を確認する。特にコーンの手前の草が反射源になる場合は画像との対応が保証できない。現在の距離・速度・パルス長は実機検証前の設定である。

配線・しきい値は[`mission/const.py`](../../mission/const.py)、各測距の取得は[`lib/sonar.py`](../../lib/sonar.py)、画像との対応条件は[`mission/goal.py`](../../mission/goal.py)、最終接近は[`mission/phases/p6.py`](../../mission/phases/p6.py)を参照する。ログ形式v2は`SonarDistanceCm`、`SonarValid`、`SonarStaleSec`、`SonarSeq`、`SonarObservedAt`、`GoalDecision`、`GoalConfirmCount`を記録する。過去の`ObstacleDist`は解析時に読み替え、投影点は障害物の確定位置ではなくソナー反射点の推定として表示する。
