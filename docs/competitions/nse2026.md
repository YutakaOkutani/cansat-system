# NSE2026 Mission Provenance

> **Audience: AI agents changing mission policy, timing, goal detection, or field tuning.** Load this page only when deciding whether an existing value is universal, airframe-specific, or inherited from NSE2026.

## Scope

- The current Phase 0–7 mission, 15-minute external envelope, 13-minute program target, red-cone goal, parachute separation, and grass-drive tuning were validated for NSE2026.
- These values are the current production behavior, but they are not universal CanSat rules.
- Preserve the `nse2026-final` Git tag, the released Gerber archive, BOM links, and historical logs as provenance-bearing assets.
- Record a new competition's rule-derived changes in its own page and source-controlled commit or tag; do not silently reinterpret NSE2026 values as generic defaults.

## Responsibility boundary

- Competition policy includes the allowed mission duration, required mission stages, goal-marker assumptions, arrival semantics, radio restrictions, and launch delay.
- Airframe configuration includes pins, physical motor mapping, direction inversion, sensor wiring, and fixed trim.
- Field/run context includes coordinates, location, surface/weather notes, operator, and test labels.
- Keep the active system single-airframe. Competition provenance does not authorize a runtime registry that dynamically patches constants.

## Change rule

Before reusing a value for another competition, identify its evidence source. Keep it unchanged only when the new rules, field, goal marker, and hardware assumptions are compatible; otherwise change the owning source and its regression tests together.

## Current goal-policy revision

- The historical NSE2026 timed final push remains provenance only. Current behavior removes sonar-only avoidance and uses stopped camera/range proximity confirmation.
- User-specified objective: vehicle contact with the cone. The front projection is estimated at about 5 cm from a photograph and is not measured. Current range-based termination does not claim verified contact or competition acceptance.
- See `../07-mission-spec.md` for active phase/termination semantics and `../../README.md` for hardware validation.

## AI Checklist

- Is the value actually generic, or only validated at NSE2026?
- Did I distinguish competition policy from airframe wiring and per-run context?
- Is historical NSE2026 provenance still identifiable?
- Did I avoid reintroducing dynamic multi-airframe overrides?
